# Ordinary disposal: pre-completion destructor audit

Baseline: `origin/main` `5eccf5060a61db0bfd2930ea182c943c1f150855` (#181, #182, #183 merged). Scope: ordinary `FiberHandle::dispose()` after its terminal claim and before `publish_dispose_complete()`. This is an ownership and ordering proof for normal public API execution, not a recovery policy for forged internal states. The caller can cancel its wait; the detached task still holds a strong `Arc<Fiber>` through `complete_claimed_dispose()`.

## Order and barriers

`dispose()` claims the inertia slot, closes the terminal gate, clones the Fiber into a detached owner and waits on `dispose_complete` (`fiber/mod.rs:968–993`). The owner brackets `teardown_body()`, abandons the slot, releases exact residency, then publishes `dispose_complete` and wakes waiters (`fiber/mod.rs:999–1025`). Within the bracket, `Unloading` is published, the slot is pinned inactive, the Fiber is marked dead and unregistered from the dependency index, cleanups drain, `Disposed` is published, and the normalized error is cleared (`fiber/mod.rs:1044–1073`). `Disposed` plus an idle slot can answer `ready()` **before** exact unlink and the complete barrier; neither is a substitute for `dispose()` completion.

| Destruction seam | Public-path ownership and reachability | State at the seam; containment and effect |
| --- | --- | --- |
| `transition(Unloading)` Service drift's `affected` and retained Registry snapshots | A user can dispose a dependent after the provider's semantic snapshot, leaving the snapshot as its last `Arc<Fiber>`. `CommittedServiceDrift::kick()` destroys each affected and retained Fiber separately inside `contain()` (`service.rs:321–351`). | The disposing Fiber still owns its slot, is Closing and at `Unloading`; its cleanup, `Disposed`, unlink and complete flag are outstanding. A dependent `Input::Drop` panic is contained per item, so later kicks and owner teardown continue. This also covers the `drift.kick()` before observation in `transition()` (`fiber/mod.rs:580–609`). |
| Dependency-index `unregister()` and local `root` in `teardown_body()` | The reverse index holds `FiberId` and `Weak<Fiber>`, not user payloads (`deps.rs:23–33, 88–100`). The local `Arc<Root>` is backed by the same live Fiber's stored spawn root, so its drop cannot be the root's last reference. | Slot owned and pinned inactive, dead mark set; `Disposed`, unlink and complete flag pending. No last user value is released here. |
| Claimed `Cleanup` and its captures in `run_tokens_contained()` | Every normal `Context` effect enters the journal. Claim moves the cleanup out under the lock; `execute_cleanup()` calls and awaits it inside `catch_contained()` (`effect.rs:94–109`, `fiber/mod.rs:726–756`). Dropping captures, future output/error and panic payload is covered by this boundary; per-item failure reporting continues the LIFO drain. | Slot owned, `Unloading`, dead and unregistered; Registry still linked, complete flag false. A panicking callback or captured user value becomes one normalized failure and does not skip later cleanups. The `drain_cleanup` and token snapshots contain only framework state/keys. |
| Cleanup failure logger/exporter snapshot | A public exporter can remove itself or another exporter while a cleanup failure is being logged. The dispatch snapshot could then hold the last exporter `Arc`; `dispatch()` contains each callback and its separate snapshot destruction (`logger.rs:333–375`). The logger's `Arc<LoggerService>` also remains in the live Fiber's root. | Same drain phase as above. Exporter `Drop` panic is reported and the next exporter/cleanup proceeds. The `report_logger` and `logger` temporaries cannot be the last root or logger-service reference here. |
| `transition(Disposed)` observation records and observer callback snapshot | `FiberState` and `ServiceVisibility` records carry owned strings, `FiberId`, a framework-only realm membership and an occurrence ID (`observation.rs:125–174`, `service.rs:56–64, 241`). A callback snapshot may become the last `Arc` if a public observer is concurrently unregistered. On a normal Tokio disposal, `publish()` moves each callback and record into a detached task whose invocation/await runs in `catch_contained()` (`observation.rs:298–329`); unregister itself runs as a contained cleanup (`observation.rs:291–295`). There is no source-operation await on observer delivery. | `Disposed` is visible while the slot is still owned; error clearing and unlink are pending. Callback execution or capture destruction in its contained delivery cannot unwind the disposal owner; observer completion is deliberately not part of the terminal barrier. A Runtime observation is a notification, not proof of `dispose_complete`. |
| `store_error(None)` | The parked failure is normalized `PluginFailure { kind, diagnostic: String }`, not the original user error or panic payload (`fiber/mod.rs:677–687`, `fiber/spawn.rs:93–128`). | `Disposed` published, slot still owned; unlink and complete flag pending. Dropping the old value cannot invoke user `Drop`. |
| `ResidencyClaim::release()` group/resident/allocation temporaries | Public spawn installs the exact claim; release upgrades a `Weak<Fiber>`, removes the group and resident strong references, and drops those temporaries outside Registry locks (`registry.rs:92–108, 198–235`). The disposal owner's captured `Arc<Fiber>` is still alive, as is the `&Arc<Self>` in `complete_claimed_dispose()`. Empty group prune owns no remaining Fiber. Thus these removed Arcs cannot trigger final `Plugin::Input::Drop` here, even if the caller dropped every handle. | Slot already idle and `Disposed` published; exact unlink becomes complete during release, but `dispose_complete` remains false. The strong owner reference is the proof against a pre-barrier Fiber destructor; this release is not independently contained. |
| `release_residency()` snapshot and `FiberResidency::Removed` observation | `fiber_snapshot()` copies a name, state and `FiberId`, with no `Arc<Fiber>` or user value (`observation.rs:355–385, 421–442`). The copied `Arc<Root>` has the live Fiber's stored root behind it. The observation hub uses the callback delivery behavior above. | Slot idle, `Disposed` published, Registry unlinked; complete flag is still false until `publish_dispose_complete()` returns. No uncontained last user reference is destroyed by the snapshot/record. |

The detached owner's final `Arc<Fiber>` **can** own the last `Plugin::Input` (and other retained spawn values) after all callers drop their handles. Its release occurs only after `publish_dispose_complete()` returns, as established in `docs/dispose-owner-drop-review.md`; that reachable diagnostic-only panic cannot strand a waiter or skip cleanup. A surviving waiter itself holds another strong reference. External callers can destroy their own last user references at unrelated sites; this audit does not claim those destructors are contained by Cordis.
The framework-owned `Context::remove_plugins()` owner is a separate terminal barrier. Its frozen group-member `Arc` can become the last reference **after that member's disposal barrier but before the remaining group members are processed**. This audit does not establish group-wide attempt-all or result delivery when such a destructor panics; the separate public API regression and containment for that path are in PR #185.

No pre-completion public-path defect was found in the listed seams. No recovery logic or private-state regression is warranted. The proof assumes ordinary Tokio task scheduling for the detached owner and normal, non-aborting process behavior; it does not cover runtime shutdown that permanently stops the shared completion runtime, process abort on double panic, or arbitrary future changes that introduce user-bearing fields into currently framework-only snapshot types.
