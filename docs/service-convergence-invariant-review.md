# Service convergence invariant-panic reachability review

Status: scoped source review on `origin/main` `142ef982905359ccfadae66771487ce0544a42e1` (2026-09-26). This is evidence, not a change to the public contract. See [ADR 0031](adr/0031-service-convergence-tracks-exact-publication-assignments.md) and [the lifecycle review guide](lifecycle-concurrency-review-guide.md).

## Conclusion and ownership argument

No ordinary public API, Plugin callback, or user-owned `Drop` path found here can make the Service convergence task reach a framework invariant panic. The unit test `fiber::inertia::tests::detached_convergence_invariant_panic_is_reported_and_remains_panicked` constructs `ACTIVE` without a target by directly calling private `try_claim()` and `spawn_convergence_pass()`. It proves the diagnostic and orphaned slot **given that corrupt state**, not public reachability.

For a live installed dependent, `kick()` has only two paths that start the task after winning `IDLE -> ACTIVE`: with a stored target, `exit_recheck()` first records a new target on drift; without one, `kick()` computes and records the first target. If the target remains unchanged, it releases the slot without spawning. `pin_inactive()` can clear the target only in `teardown_body()`, whose caller already owns the same slot. Concurrent disposal waits to claim it; teardown marks the fiber dead before releasing the slot, and later kicks refuse dead fibers. A kick winning in the creation window records its target before task submission, while the initial pass arbitrates through `try_claim()`/`claim()`.

## Exceptional exits, in execution order

| --- | --- | --- |
| `kick()` before claim (`inertia.rs:353–384`) | Service mutation may commit off-runtime; a Service value or rejected publication can panic in `Drop` around the caller's kick. | No task or slot is lost. The revision remains outstanding and `FiberHandle::ready()` drives it when a runtime is available (`fiber/mod.rs:1517–1531`). An off-runtime kick racing `RELEASING` hands the recheck to the existing holder. |
| `kick()` after winning `IDLE -> ACTIVE` (`inertia.rs:385–409`) | Target clone, reconstruction, recording, and inline `exit_recheck()`. | Target fields contain framework-owned `Arc<()>` input identity, dependency names, and `Arc<u8>` publication identity. Reconstruction reads installed spawn state and ServiceStore; it does not clone or destroy `Plugin::Input` or Service values. Public spawn installs state before exposing dependency edges. No user callback or destructor runs between claim and release/handoff. |
| `spawn_convergence_pass()` (`inertia.rs:431–442`) | Logger construction, context formatting, completion-runtime spawn. | Fiber name is an owned `String`; logger construction invokes no exporter. The task starts on the shared completion runtime (`effect.rs:553–561`); dropping its `JoinHandle` does not abort it. No ordinary user callback runs in this handoff. |
| `convergence_pass()` target read (`inertia.rs:571–575`) | `current_target()` panics on `None`. | The private malformed-state test can cause this; public disposal cannot clear the target while the convergence holder owns the slot. Missing installed spawn state in `compute_target()` or `apply_snapshot()` also requires bypassing public spawn installation. |
| `settle_once()` (`fiber/mod.rs:848–949`) | Plugin apply, its future, `ApplyError::to_string`, cleanup callback/captures, panic payload `Drop`, logger exporter. | Apply runs inside `catch_contained()` and publishes `Failed` after rollback. Cleanup call/poll runs in `execute_cleanup()` containment; `consume_panic_payload()` contains secondary destructor panics; exporter callbacks are contained. `Plugin::Input` remains retained by the typed seal during convergence. Observer callbacks run in separate contained tasks. Public-path payload and exporter `Drop` regressions are in `service_convergence_owner.rs`. |
| `exit_recheck()` (`inertia.rs:296–341`) | Reconstruction, target replacement, and `Err(other)` from final CAS. | Target reconstruction/replacement uses only framework-owned identities. The holder writes `RELEASING`; a kick may change it to `ACTIVE`, which the holder handles by rechecking. Other claimants require `IDLE` and cannot change this holder's `RELEASING` state. `Err(IDLE)` or another value requires a non-owner release or private corruption. Keep the invariant panic. |
| `kick()`'s `other` state (`inertia.rs:412`) | Atomic word outside `IDLE`, `ACTIVE`, `RELEASING`. | Ordinary writers use only those three constants; public APIs cannot write the word. Keep the invariant panic. |

## Proof boundary and verification

This source audit concerns ordinary safe API execution. It assumes no private-state mutation, memory corruption, process-level allocation failure, executor sabotage, or indefinitely blocked user callback/cleanup. It is not an unbounded progress theorem. Reduced Loom models do not run actual Tokio tasks, user destructors, or ServiceStore reconstruction. Public-path Tokio regressions cover selected real executions, not every scheduling history. A future user destructor after the `IDLE -> ACTIVE` claim, target clear without a slot claim, or new state writer would require another review.

On this baseline: `cargo test -p cordis-core --test service_convergence_owner` (2 passed), `cargo test -p cordis-core --lib fiber::inertia::tests` (22 passed), and `cargo test -p cordis-core --test owner_panic_barriers` (3 passed). The private malformed-state test does not warrant terminal-barrier recovery logic.
